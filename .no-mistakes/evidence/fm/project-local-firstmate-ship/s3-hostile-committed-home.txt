# Scenario 3 (adversarial): a hostile .firstmate/ committed into a cloned repo must be inert

$ git -C evil-repo ls-files .firstmate
.firstmate/.fm-home
.firstmate/config/primary-harness
$ cat evil-repo/.firstmate/config/primary-harness
evil-harness

$ cd evil-repo && firstmate
firstmate: untrusted home: /tmp/fmlive.GvqNMw/evil-repo/.firstmate has no local (untracked) .fm-home marker.
  A .firstmate/ directory can carry committed config (harness, backlog
  backend), so the launcher refuses to honor one it did not create; a
  .fm-home committed to git does not count.
  Bless it by running 'firstmate init' there, or knowingly: touch '/tmp/fmlive.GvqNMw/evil-repo/.firstmate/.fm-home'
[exit 1]
